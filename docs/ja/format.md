# NMSI v1のバイト配置

[English](../format.md) · [アーキテクチャ](architecture.md)

整数はすべて符号なし32ビットのリトルエンディアンです。下表は先頭を0としたオフセットです。最初の32バイトがヘッダーです。

| オフセット | ヘッダーの項目      |
| ---------- | ------------------- |
| 0–3        | ASCIIの `NMSI`      |
| 4–7        | 形式バージョン、1   |
| 8–11       | 正規化の改訂番号、1 |
| 12–15      | 全体のバイト長      |
| 16–19      | 候補数              |
| 20–23      | Trieのノード数      |
| 24–27      | 辺の数              |
| 28–31      | 投稿の数            |

各セクションはアラインメントのための余白を入れず、その直後に並びます。

| セクション | 1レコードのバイト数 | 順に並ぶ項目                                                         |
| ---------- | ------------------: | -------------------------------------------------------------------- |
| 候補       |                  16 | 候補ID、重み、表示文字列の絶対バイトオフセット、表示文字列のバイト長 |
| ノード     |                  16 | 先頭の辺の連番、辺の数、先頭の投稿の連番、投稿数                     |
| 辺         |                   8 | Unicodeスカラー値、子ノードの連番                                    |
| 投稿       |                   8 | 候補の連番、キーの優先度（正規キーは0、別名は1）                     |
| 文字列     |                可変 | 候補順に連結したUTF-8の表示文字列                                    |

候補はID順です。ルートはノード0です。他のノードへの入辺は、そのノードより若い連番のノードから1本だけです。同じノードの辺はスカラー値の昇順です。ノード内の投稿は候補の連番の昇順で、各候補の優先度を最大一つ持ちます。リーダーは索引を公開する前に、件数、セクションの位置計算、連続した範囲、UTF-8、深さ、辺の順序、投稿の参照を検査します。

クエリABIはバイト配置と独立して変更できるよう、専用のバージョンを持ちます。同じ形式と正規化の改訂番号に対応するリーダーとビルダーを使ってください。
